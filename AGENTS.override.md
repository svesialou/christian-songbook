# AGENTS.override

## Режим запуска (обязательное правило)
На старте проекта используется **MVP-only**:
- без регистрации/авторизации;
- без live-синхронизации и без admin mutation API;
- без серверного хранения пользователей и ролей;
- без деплоя в прод без отдельного отдельного решения.

Read-only backend API для опубликованного каталога и MySQL foundation допустимы в фазе 1.5, если PWA остается offline-first и обычный пользователь не видит admin tools.

## Что строго запрещено в фазе 1
- Реализовывать реальное multi-device синхронизированное управление словами в реальном времени.
- Делать архитектурные предположения под онлайн только на этапе 2.
- Добавлять платежи/подписки/ads.

## Что разрешено в фазе 1
- Офлайн-first единый каталог, поставляемый вместе с приложением,
- режимы отображения:
  - с аккордами / без аккордов;
  - повтор рефрена;
  - смена тоники;
  - закладки (избранное);
  - поиск по тексту.
- PWA-инсталляция, кэш приложения и кэш данных.

## Критические требования
- Корректная работа без интернета после первичной установки каталога, поставляемого вместе с приложением.
- Ясный fallback если формат данных неверный.
- Импорт/экспорт каталога не показывать обычному пользователю; эти инструменты допустимы только для admin-preview/админского сценария.
- После каждого цикла разработки обязательно проверять frontend на актуальной локальной/full-stack сборке по `docs/development-quality-gates.md`.
- Любой финальный отчет должен явно разделять выполненные проверки и непроверенные риски. Нельзя писать "проверено", если проверка была только предположена.

## Переключение к следующей фазе
Переход к фазам 2/3 только после закрытия DoD фазы 1 и подтверждения, что офлайн-режим стабилен на мобильном и десктопе.
