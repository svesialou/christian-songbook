# Оценка референсного репозитория
**URL:** https://github.com/pavelliolia/christian-songs-mobile-app

## Что есть в референсе
- React Native приложение (не web).
- Используется стэк RN 0.63.2 (устаревший).
- Загрузка песен с API `https://quiet-sierra-94562.herokuapp.com` через `fetch`.
- Данные хранятся локально в Redux (`redux-persist` + `AsyncStorage`).
- Есть полезные UX-решения для базового сборника:
  - список песен + поиск (Fuse.js),
  - детальная карточка с куплетами/припевами,
  - переключатель аккордов,
  - транспонирование,
  - повтор припева,
  - пользовательские пометки/подборки,
  - темная тема.

## Ограничения для задачи
- Нет PWA и web-архитектуры как базового слоя.
- Есть зависимость от внешнего API и устаревшая инфраструктура.
- Нет явного механизма офлайн-синхронизируемого live-режима.
- README минимальный (практически только описание проекта).

## Что целесообразно переиспользовать как идея
- Модель `Song` (куплеты, припев, мост, аккорды).
- UX-паттерны: быстрый поиск, режимы показа/скрытия аккордов, пользовательские подборки.
- Концепция модальных экранов настроек.

## Что НЕ переносим 1-в-1
- Конкретный RN стек и зависимые экраны/навигацию.
- Бэкенд Heroku-зависимость для базового офлайн-сценария.
- Глобальный Redux как единственный источник правды для live-синхронизации без контрактов.

## Риск-лист
- Лицензии/авторские права на тексты.
- Конфликт форматов источника (если несколько источников песен).
- Недостаточный контроль за состоянием «что поётся сейчас» для live.
