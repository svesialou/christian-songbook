# Задачи — Фаза 1.5 (Backend + MySQL foundation)

## 1. Backend stack decision
- **Цель:** подтвердить backend stack: Go API + MySQL по умолчанию или другой стек по отдельному решению.
- **Критерий приёмки:** выбран стек, описаны причины, команды запуска, базовая структура проекта.
- **Критерий отмены:** нет подтверждения по стеку или backend пока не нужен для реального каталога.
- **Зависимости:** фаза 1 user-flow без импорта/экспорта для обычного пользователя.

## 2. Docker-first local backend
- **Цель:** подготовить локальный запуск backend + MySQL параллельно с PWA.
- **Критерий приёмки:** backend и MySQL стартуют локально одной командой или Makefile target, PWA остаётся доступна на своём порту.
- **Критерий отмены:** конфликт портов или нет согласованного runtime.
- **Зависимости:** задача 1.

## 3. Draft MySQL schema and migrations
- **Цель:** спроектировать таблицы каталога песен, версий каталога и будущих пользовательских связей.
- **Критерий приёмки:** есть forward migration draft, rollback notes, индексы под list/search/song detail.
- **Критерий отмены:** нет подтверждения модели `Song` и требований к поиску.
- **Зависимости:** задача 1.

## 4. Read-only catalog API
- **Цель:** дать frontend единый источник каталога без пользовательского импорта.
- **Критерий приёмки:** API отдаёт список песен, одну песню и текущую версию каталога; запросы параметризованы.
- **Критерий отмены:** нет утверждённой схемы.
- **Зависимости:** задача 3.

## 5. Admin-only catalog management plan
- **Цель:** определить admin flow для импорта/редактирования/публикации каталога.
- **Критерий приёмки:** обычный пользователь не видит import/export; admin mutation API требует auth в будущей реализации.
- **Критерий отмены:** нет решения по auth/admin доступу.
- **Зависимости:** задача 4.

## 6. PWA catalog snapshot sync
- **Цель:** синхронизировать опубликованную MySQL-базу в локальный snapshot PWA.
- **Критерий приёмки:** при наличии сети PWA обновляет snapshot, без сети продолжает читать локальный каталог.
- **Критерий отмены:** backend не отдаёт стабильный `catalogVersion`.
- **Зависимости:** задача 4.

## 7. Future user-link preparation
- **Цель:** подготовить модель для сборников, setlists и ролей без включения auth в обычный MVP.
- **Критерий приёмки:** описаны таблицы и API-контуры для `users`, `user_collections`, `user_collection_items`, `setlists`, `live_sessions`.
- **Критерий отмены:** нет подтверждения сценариев пользователей.
- **Зависимости:** задача 3.
- **Статус:** добавлен planning draft в `docs/backend-mysql-plan.md`: `users`, `user_collections`, `user_collection_items`, `setlists`, `setlist_items`, `live_sessions`, `live_participants`, основные access patterns, индексы и правила data safety без production migrations/auth/API.
