# Задачи — Фаза 1 (MVP)

## 1. Инициализация проекта
- **Цель:** создать Vite+React+TS проект, базовый роутинг, PWA-setup.
- **Критерий приёмки:** запускается локально, работает `npm run dev`, установка PWA доступна.
- **Критерий отмены:** блокируются зависимостями от платформы или старые RN-библиотеки.
- **Зависимости:** AGENTS + architecture.

## 2. Модель песни и репозиторий каталога
- **Цель:** реализовать `Song`, `Section`, `SongStore` для единого встроенного каталога.
- **Критерий приёмки:** обычный пользователь получает список песен без ручного импорта, admin-preview не влияет на user-flow.
- **Зависимости:** задача 1.
- **Статус:** добавлена категория песни с fallback `Общее` для старых локальных данных и будущих backend snapshots.

## 3. Экран списка
- **Цель:** отображение списка, поиск, навигация в песню.
- **Критерий приёмки:** поиск < 300мс на выборочном каталоге, переход к песне работает.
- **Зависимости:** задача 2.
- **Статус:** добавлены прямые preview-состояния `?menu=1` и `?song=<id>` для проверки меню, списка и экрана песни без дополнительных тестовых кнопок в UI.
- **Статус:** добавлен компактный фильтр категорий поверх списка, недавних и сборников.
- **Статус:** для нескольких категорий добавлен overflow `...` с нижним searchable picker вместо длинного ряда chips.

## 4. Экран песни
- **Цель:** отрисовка структуры verse/chorus/bridge, toggle аккордов.
- **Критерий приёмки:** при выключенных аккордах текст читается без «зазоров»; при включении показываются только доступные аккорды.
- **Зависимости:** задача 2,3.

## 5. Транспонирование и repeat
- **Цель:** контролы смены тональности и повтора припева.
- **Критерий приёмки:** на уровне UI изменения мгновенные без потери позиции в тексте.
- **Зависимости:** задача 4.
- **Статус:** усилено: транспонирование нормализуется в понятный диапазон и поддерживает бемоли/slash-chords в отображении аккордов.

## 6. Сборники, недавние и persistence
- **Цель:** добавить пользовательские сборники, недавние песни и сохранение/чтение настроек.
- **Критерий приёмки:** сборники, недавние песни и настройки выживают после закрытия браузера.
- **Зависимости:** задача 1,3.

## 7. Офлайн и кэш
- **Цель:** после первой установки и загрузки каталога приложение работает без интернета.
- **Критерий приёмки:** production build содержит `dist/sw.js` с precache реальных hashed assets; при отключенной сети список и открытие песни работают на локальном snapshot/embedded catalog.
- **Зависимости:** задачи 1,2,3,4.
- **Статус:** усилено PWA-кэширование: production service worker получает cache name от состава app shell и регистрируется только в production-сборке.

## 8. UX-подготовка (ui-ux-pro)
- **Цель:** задать токены: spacing, типографику, контраст, целевые размеры touch.
- **Критерий приёмки:** 4.5:1 контраст в тексте, кнопки не меньше 44px по высоте.
- **Зависимости:** задача 7.
- **Статус:** добавлены базовые UI-ограничения для touch-target, focus-ring, motion timing, disabled-state и системного выделения текста без изменения структуры экранов.

## 9. Граница с будущим backend/MySQL
- **Цель:** подготовить frontend к будущему backend snapshot без зависимости от сети.
- **Критерий приёмки:** обычный read-flow не содержит import/export, каталог может быть заменён backend snapshot в фазе 1.5 без изменения UI.
- **Зависимости:** задачи 2,3,7.
- **Статус:** усилена frontend-граница backend snapshot: перед сохранением проверяется структура песен, секций, строк и аккордов.
