# Задачи — Фаза 2 (Live foundation)

## 1. Режимы профилей участников
- **Цель:** создать пресеты отображения по ролям.
- **Критерий приёмки:** один и тот же каталог открывается с разным набором видимости аккордов/текста.
- **Зависимости:** завершенная фаза 1.
- **Статус:** начат локальный foundation: `Lead`, `Singer`, `Chords` работают как локальные view presets без server-side users/live sync.

## 2. Модель setlist
- **Цель:** отдельная структура порядка песен и состояний сессии.
- **Критерий приёмки:** пользователь может создавать/редактировать порядок песен локально, а backend/MySQL модель готова к синхронизации.
- **Зависимости:** фаза 1 + фаза 1.5 backend/MySQL foundation.
- **Статус:** начат локальный precursor: пользовательские сборники создаются и наполняются песнями, по умолчанию открываются как обычные сборники, а переход в отдельный `Live` режим выполняется компактной кнопкой `Live` справа вверху. `Live` хранит отдельную локальную очередь песен (`liveSongIds`), сборник остаётся источником/базой, а внутри `Live` песни можно добавлять из выбранного сборника через отдельный поиск по источнику без изменения самого сборника; глобальный поиск/категории/редактирование сборника скрыты, песни показывают `Сейчас`/`Далее`, live-карточка переводит список на следующую песню без открытия песни и без backend sync, а компактное меню песни меняет порядок очереди или убирает песню из `Live`.

## 3. Базовая модель воспроизведения
- **Цель:** хранение `activeSongId`, `activeSection`, `activeLine` как единая структура.
- **Критерий приёмки:** UI может показать положение в песне и обновлять его локально.
- **Зависимости:** задача 2.
- **Статус:** добавлен локальный `playbackPosition`: тап по строке песни отмечает текущую строку, состояние сохраняется в IndexedDB/localStorage fallback без backend/live sync.
- **Статус:** добавлен локальный автопереход строк по metadata песни (`bpm`, `beatsPerLine`, `introBeats`) с вступлением перед первой строкой, компактным счётом до старта, прогрессом текущей строки и плавным scroll к активной строке; звуковой метроном и live sync не включались.

## 4. Режимы «репетиций» и «проекта»
- **Цель:** UI-флаги для разных сценариев (по одному экрану или проектору).
- **Критерий приёмки:** два макета режима не конфликтуют по данным.
- **Зависимости:** задача 1.
- **Статус:** projector-режим отложен. Текущий фокус — удобный онлайн/офлайн сборник и общий командный список для live-ориентации.

## 5. API-модель для будущей синхронизации (без реализации)
- **Цель:** зафиксировать контракт событий (без сетевой реализации): `position.update`, `setlist.update`, `role.update`.
- **Критерий приёмки:** есть документация и пример schema.
- **Зависимости:** задача 3.
- **Статус:** добавлен draft событий в `docs/live-sync-events.md`: общий envelope, `setlist.update`, `position.update`, `role.update`, правила ревизий/idempotency и отложенные решения без реализации транспорта/backend/API.

## 6. User-link model
- **Цель:** связать пользователей со сборниками, setlists и role presets на уровне backend/MySQL модели.
- **Критерий приёмки:** есть draft API/schema без обязательной социальной авторизации.
- **Зависимости:** фаза 1.5, задача 2.
