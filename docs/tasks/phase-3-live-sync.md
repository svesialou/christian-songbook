# Задачи — Фаза 3 (Live sync)

## 1. Транспорт синхронизации
- **Цель:** выбрать и внедрить transport (WebSocket как основной, fallback).
- **Критерий приёмки:** стабильное подключение минимум 3 клиентов и передача `position`.
- **Зависимости:** задача 5 фазы 2 + backend/MySQL foundation.

## 2. Мастер-контроллер и участники
- **Цель:** выделить роль ведущего с правами управления, остальные — только чтение.
- **Критерий приёмки:** изменения ведущего отражаются в клиентах в пределах целевого SLA (<150ms в локальной сети).

## 3. Подсветка слов в реальном времени
- **Цель:** подсвечивать текущую строку и (в будущей фазе) текущий аккорд.
- **Критерий приёмки:** при переходе по таймингу выделение синхронизировано на всех экранах.

## 4. Адаптивные экраны
- **Цель:** добавить projector-режим, без лишних UI-элементов.
- **Критерий приёмки:** главный экран читаем на проекторе при удалении от устройства.

## 5. Безопасность и устойчивость
- **Цель:** код сессии, автоотключение неактивных клиентов, повторное подключение.
- **Критерий приёмки:** после разрыва сети сессия корректно восстанавливается.

## 6. Persistent live state
- **Цель:** хранить live session, participants и текущую позицию в backend/MySQL без блокировки локального чтения.
- **Критерий приёмки:** после reconnect клиент восстанавливает актуальную позицию и роль.
- **Зависимости:** backend/MySQL schema для `live_sessions` и `live_participants`.
